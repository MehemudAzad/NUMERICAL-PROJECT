Part one

The project in plain terms

What an image generator is doing

When an AI generates an image it starts from pure static and gradually cleans it up until a picture appears. The cleanup follows a rule that says, at every moment: given the messy picture you are holding now, here is the direction to nudge it. Follow that rule from static to finish and you have an image.

Rules of that shape are differential equations, and solving them numerically is one of the oldest problems in this field — the same machinery used to predict where a planet will be next year. You advance in small hops, checking the direction as you go.

Why the number of hops is the whole game

Every time you ask "which direction now?", you have to evaluate a large neural network. That query is slow, and it is essentially the entire cost of making an image. So the question that matters is how few times you can ask before the picture falls apart.

Small hops give a beautiful image after 250 queries. Big hops are fast but drift off course into garbage. Everything in this project lives in that tension. The unit of cost is NFE — number of function evaluations, meaning network calls.

What the base paper contributed

The direction rule has two ingredients mixed together. One is simple and predictable — solvable exactly with algebra, no approximation needed. The other is the messy neural network part.

Everyone before had been approximating both at once, which wastes error budget on the half you could have had exactly for free. Lu et al. solved the easy half exactly and spent all their approximation on the hard half. Good images in 10–20 network calls instead of 100–250, with no retraining.

What you are adding

The paper proves its method works and shows the pictures look good. "Looks good" is measured by FID, a score comparing generated images to real ones as a group. That is an image-quality question, not a numerical one. A numerical analyst grades a solver on three different things:

  • Order. Halve the step size — how much more accurate does the answer get? Twice? Eight times? Theory predicts an exact number per method. Nobody checked it directly against known-correct trajectories.
  • Stability. How large a step before the computation explodes? Worst near the very end of the cleanup, where the equation turns nasty. Section 4.2 of the paper asserts that classical methods go unstable here and cites the literature, but never measures it. That is the ideal setup for you.
  • Cost. Higher-order methods are more accurate per step but call the network more times per step. Divide it out — is the fancy method still ahead?

Why toy problems, and why three of them

To measure how wrong a solver is, you need the right answer. For a real image nobody knows the right answer — that is the point of generating it. So you deliberately build baby versions of the problem, simple enough to write the exact correct answer down with algebra. Now error is measurable.

Then you repeat at increasing realism. Testing a car on a measured flat track, then a winding road, then real traffic. A solver that wins on all three tells you something about the method; one that only wins on the track tells you about the track.

The validation suite. Moving right trades exactness of the reference for realism of the problem.

There is a sharper reason for this structure than "increasing realism." The paper's order theorem rests on Assumption B.1: that the derivatives of the network with respect to λ exist and are continuous up to order k+1. A neural network has no obligation to satisfy that. Your Tiers 1 and 2 satisfy it exactly, because their scores are analytic. Tier 3 probably does not. So the suite is a direct test of whether the theorem's hypotheses hold in practice — a much stronger claim than the coverage argument in your current deck.

One line

Generating an image is following a path, one expensive hop at a time. This project asks which way of hopping is genuinely best, judged by the standards mathematicians have used for a century rather than by whether the picture happens to look pretty.

Part two

The formulas you will code

This is the complete mathematical content of the project. Everything else is plumbing.

The noise schedule (variance-preserving, linear)

Fixed constants β₀ = 0.1, β₁ = 20, matching the paper. t runs from 1 down to t_end.

signal and noise levels log α(t) = −(β₁−β₀)/4 · t² − β₀/2 · t σ(t) = sqrt(1 − α(t)²) β(t) = β₀ + t(β₁−β₀) drift and diffusion f(t) = d log α/dt = −½ β(t) g²(t) = β(t) half log-SNR — the good time variable λ(t) = log α(t) − log σ(t) t(λ) = 2·u / ( sqrt(β₀² + 2(β₁−β₀)u) + β₀ ), u = log(e^(−2λ) + 1)

The equation being solved

ε is the noise-prediction model: either a neural network, or in Tiers 1 and 2 an exact formula you write yourself.

probability-flow ODE in t — what arm A integrates dx/dt = f(t)·x + g²(t)/(2σ(t)) · ε(x, t) the same ODE in λ — what arm B integrates (paper, eq. E.1) dx/dλ = σ̂(λ)²·x − σ̂(λ)·ε(x, λ) where α̂(λ) = 1/sqrt(1 + e^(−2λ)), σ̂(λ) = 1/sqrt(1 + e^(2λ)) DPM-Solver-1 — one step, arm C (paper, eq. 3.7) x_i = (α_i/α_{i−1})·x_{i−1} − σ_i·(e^h − 1)·ε(x_{i−1}, t_{i−1}), h = λ_i − λ_{i−1}

The exact answer for Tier 1

This is the key that makes the project tractable. Take data drawn from a Gaussian with covariance Σ. Diagonalise once, so Σ becomes a list of eigenvalues s. Then the noised distribution at time t is Gaussian with variance v = α²s + σ² per coordinate, and both the score and the exact trajectory are one-liners.

exact noise oracle — feed this to any solver ε*(x, t)_j = σ(t) · x_j / (α(t)²·s_j + σ(t)²) exact solution — no integration, pure algebra x_j(t) = x_j(T) · sqrt( v_j(t) / v_j(T) ), v_j(t) = α(t)²·s_j + σ(t)²

Why that solution is right: the ODE in each eigen-coordinate collapses to dx/dt = [f + g²/(2v)]·x, which is linear, so the flow is multiplication by a scalar. The flow preserves the marginals, which are Gaussian with variance v(t), and the only increasing linear map taking variance v(T) to v(t) is multiplication by sqrt(v(t)/v(T)). It checks out by differentiation: you need v' = 2fv + g², and substituting the definitions gives 2αα's + 2σσ' on both sides.

The stiffness knob is the condition number κ = s_max / s_min. That is the quantity you sweep.

The exact answer for Tier 2

Replace the single Gaussian with a mixture of points μ₁…μ_K (weights w_k). The noised density stays a mixture, so the score stays closed-form — now with genuine curvature. Sample the μ from a Swiss roll and you get a curved manifold with an exact score.

r_k ∝ w_k · exp( −‖x − α(t)·μ_k‖² / (2σ(t)²) ) softmax weights x̂₀ = Σ_k r_k · μ_k posterior mean ε*(x,t) = ( x − α(t)·x̂₀ ) / σ(t)

The three arms

DPM-Solver's advantage comes from two separable ideas: treating the linear half exactly, and changing the time variable to λ. Run all three arms to separate them.

  • Arm A — classical explicit methods on the raw ODE, uniform steps in t
  • Arm B — the same methods on the λ-form ODE, uniform steps in λ
  • Arm C — DPM-Solver 1, 2, 3, which are exact on the linear part

A versus B isolates the reparameterisation. B versus C isolates the exact linear treatment.

Correction to what I told you earlier

I said Euler-in-λ is identical to DPM-Solver-1, and offered that as your machine-precision sanity check. That is wrong. Plain forward Euler on the λ-ODE keeps the σ̂²x term inside the approximation; DPM-Solver-1 handles it exactly. They agree only to first order, differing at O(h²).

The identity that does hold exactly is DDIM = DPM-Solver-1 (paper §4.1), and that is your gate. The Euler-λ versus DPM-Solver-1 gap is not a bug — it is the measurement of what exact linear treatment buys you at first order. Better outcome, but I should have got it right the first time.

Also worth knowing: Table 1 of the paper already runs a three-arm FID comparison, so this is not virgin territory. Reframe it as extending the paper's own ablation from sample quality to discretization error and stability. You gain a published table to validate against, and their exact schemes to copy.

Noise schedule

Half a day. Owner: whoever takes the solver workstream.

src/schedule.py

import numpy as np

BETA_0, BETA_1 = 0.1, 20.0

def log_alpha(t):
    t = np.asarray(t, dtype=np.float64)
    return -(BETA_1 - BETA_0) / 4.0 * t**2 - BETA_0 / 2.0 * t

def alpha(t):  return np.exp(log_alpha(t))
def beta(t):   return BETA_0 + np.asarray(t, np.float64) * (BETA_1 - BETA_0)
def f(t):      return -0.5 * beta(t)          # d log alpha / dt
def g2(t):     return beta(t)

def sigma(t):
    la = log_alpha(t)
    return np.sqrt(-np.expm1(2.0 * la))       # stable sqrt(1 - alpha^2)

def lmbda(t):
    """Half log-SNR. Strictly decreasing in t."""
    la = log_alpha(t)
    return la - 0.5 * np.log(-np.expm1(2.0 * la))

def t_of_lmbda(l):
    """Inverse of lmbda. Paper appendix D.4, stable form."""
    l = np.asarray(l, np.float64)
    u = np.logaddexp(0.0, -2.0 * l)           # log(e^{-2l} + 1)
    return 2.0 * u / (np.sqrt(BETA_0**2 + 2.0*(BETA_1-BETA_0)*u) + BETA_0)

# --- lambda-domain coefficients, paper eq. E.1 ---
def alpha_hat(l): return 1.0 / np.sqrt(1.0 + np.exp(-2.0*np.asarray(l, np.float64)))
def sigma_hat(l): return 1.0 / np.sqrt(1.0 + np.exp( 2.0*np.asarray(l, np.float64)))

    t  = np.linspace(0.05, 0.95, 40); dt = 1e-6
    fd = (log_alpha(t+dt) - log_alpha(t-dt)) / (2*dt)
    assert np.allclose(fd, f(t), rtol=1e-6)

def test_g2_identity():
    """g^2 = -2 sigma^2 dlambda/dt  (paper eq. 3.2)."""
    t  = np.linspace(0.05, 0.95, 40); dt = 1e-6
    dl = (lmbda(t+dt) - lmbda(t-dt)) / (2*dt)
    assert np.allclose(-2*sigma(t)**2*dl, g2(t), rtol=1e-6)

Run python -m pytest tests -q. All four must pass. λ is monotonically decreasing in t, so t = 1 gives the most negative λ and small t gives large λ. Getting that direction backwards is the single most common bug in this project.

Tier 1 testbed, with its exact answer

One day. Owner: testbed workstream.

src/testbeds.py

import numpy as np
from .schedule import alpha, sigma, f, g2, sigma_hat

class GaussianTier1:
    """Data ~ N(0, diag(s)).  Exact score and exact trajectory."""

    def __init__(self, kappa, d=2, seed=0):
        # eigenvalues log-spaced over the requested condition number
        self.s = np.logspace(0, np.log10(kappa), d) if d > 1 else np.array([1.0])
        self.s = self.s / self.s.max()          # normalise so s_max = 1
        self.d, self.kappa = d, kappa
        self.rng = np.random.default_rng(seed)

    def var(self, t):
        return alpha(t)**2 * self.s + sigma(t)**2

    def eps(self, x, t):
        """Exact noise-prediction oracle. Same signature as a network."""
        return sigma(t) * x / self.var(t)

    def rhs_t(self, x, t):
        """Probability-flow ODE in t."""
        return f(t)*x + g2(t)/(2.0*sigma(t)) * self.eps(x, t)

    def rhs_lambda(self, x, l):
        """Same ODE in lambda. Paper eq. E.1."""
        from .schedule import t_of_lmbda
        t = t_of_lmbda(l)
        return sigma_hat(l)**2 * x - sigma_hat(l) * self.eps(x, t)

    def exact(self, x_T, T, t):
        """Closed-form solution. No integration."""
        return x_T * np.sqrt(self.var(t) / self.var(T))

    def x_T(self, n=1):
        return self.rng.standard_normal((n, self.d)) * np.sqrt(self.var(1.0))

def test_exact_satisfies_ode():

        ana = tb.rhs_t(tb.exact(xT, T, t), t)
        assert np.allclose(num, ana, rtol=1e-5), t

def test_score_matches_monte_carlo():
    """Analytic epsilon vs. an empirical estimate from forward samples."""
    tb  = GaussianTier1(kappa=10.0, d=3, seed=1)
    rng = np.random.default_rng(2)
    from src.schedule import alpha, sigma

        e   = rng.standard_normal((400_000, 3))
        xt  = a*x0 + sg*e
        # E[eps | xt] estimated by binning is fiddly; instead check the
        # implied marginal variance, which pins down the same quantity.
        assert np.allclose(xt.var(axis=0), tb.var(t), rtol=2e-2), t

Classical solvers, arm A

One day. Use the paper's exact schemes, not generic textbook ones.

Appendix E.4 specifies which classical methods were used: explicit midpoint for RK2 and Heun's third-order with r₁ = 1/3, r₂ = 2/3 for RK3. That r choice deliberately mirrors DPM-Solver-3. If you substitute generic Heun or classical RK4, your numbers will not be comparable to Table 1.

src/solvers.py

import numpy as np

def euler(rhs, x, a, b):
    h = b - a
    return x + h * rhs(x, a)

def midpoint(rhs, x, a, b):
    """RK2 as used in the paper (appendix E.4)."""
    h = b - a
    u = x + 0.5*h * rhs(x, a)
    return x + h * rhs(u, a + 0.5*h)

def heun3(rhs, x, a, b):
    """RK3, Heun's third-order, r1=1/3 r2=2/3 (appendix E.4)."""
    h = b - a
    r1, r2 = 1.0/3.0, 2.0/3.0
    k1 = rhs(x, a)
    u1 = x + r1*h*k1
    u2 = x + r2*h*rhs(u1, a + r1*h)
    k3 = rhs(u2, a + r2*h)
    return x + h*(0.25*k1 + 0.75*k3)

def rk4(rhs, x, a, b):
    h = b - a
    k1 = rhs(x, a)
    k2 = rhs(x + 0.5*h*k1, a + 0.5*h)
    k3 = rhs(x + 0.5*h*k2, a + 0.5*h)
    k4 = rhs(x + h*k3,     a + h)
    return x + h/6.0*(k1 + 2*k2 + 2*k3 + k4)

NFE_PER_STEP = {"euler":1, "midpoint":2, "heun3":3, "rk4":4}
STEPPERS     = {"euler":euler, "midpoint":midpoint, "heun3":heun3, "rk4":rk4}

def integrate(rhs, x0, grid, stepper):
    """March over a fixed grid. Returns final state and NFE spent."""
    step = STEPPERS[stepper]
    x = np.array(x0, dtype=np.float64, copy=True)
    for a, b in zip(grid[:-1], grid[1:]):
        x = step(rhs, x, a, b)
        if not np.all(np.isfinite(x)):
            return x, np.nan          # diverged
    return x, NFE_PER_STEP[stepper] * (len(grid) - 1)

Two accounting traps

NFE is not steps. RK4 spends four network calls per step. Every plot must use measured NFE, never step count. Getting this wrong makes RK4 look like a free win.

Order is defined in h, not NFE. Fit both slopes and report both. Error against h gives the theoretical order p. Error against NFE gives the cost-normalised order, which is what practitioners care about. State the relationship or a reader will think you made an arithmetic mistake.

The step size for arm B is h = (λ(t_end) − λ(T)) / n. For arm A it is (t_end − T) / n. These are different units, so when you compare arms, plot against NFE, not h. Use h only within an arm, for order fitting.

DPM-Solver, arm C

One day. The payoff step.

Write DPM-Solver-1 yourself — it is four lines and you need it for the gate. For orders 2 and 3, use the authors' code with your analytic oracle plugged in.

src/dpm.py

import numpy as np
from .schedule import alpha, sigma, lmbda, t_of_lmbda

def dpm_solver_1(eps_fn, x, t_prev, t_cur):
    """Paper eq. 3.7. Identical to a DDIM step."""
    l_prev, l_cur = lmbda(t_prev), lmbda(t_cur)
    h = l_cur - l_prev
    return (alpha(t_cur)/alpha(t_prev)) * x \
           - sigma(t_cur) * np.expm1(h) * eps_fn(x, t_prev)

def ddim_step(eps_fn, x, t_prev, t_cur):
    """Paper eq. 4.1, written in its original form."""
    a_p, a_c = alpha(t_prev), alpha(t_cur)
    s_p, s_c = sigma(t_prev), sigma(t_cur)
    return (a_c/a_p)*x - a_c*(s_p/a_p - s_c/a_c) * eps_fn(x, t_prev)

Note np.expm1(h) rather than np.exp(h) - 1. Appendix D.6 calls this out: for small h the naive form loses precision catastrophically, and small h is exactly where you are measuring.

Wiring the authors' solver to your analytic oracle

Their DPM_Solver never inspects the model — it just calls model_fn(x, t) → noise. So an exact formula works as well as a network, which is what lets you test the real published implementation with zero neural error.

import torch
from src.dpm_solver_pytorch import NoiseScheduleVP, DPM_Solver

ns = NoiseScheduleVP(schedule='linear', continuous_beta_0=0.1, continuous_beta_1=20.)

s_t = torch.tensor(tb.s, dtype=torch.float64)

def model_fn(x, t):
    # t arrives as a tensor; broadcast against the eigenvalue vector
    a = ns.marginal_alpha(t).reshape(-1, 1)
    g = ns.marginal_std(t).reshape(-1, 1)
    return g * x / (a**2 * s_t + g**2)

solver = DPM_Solver(model_fn, ns, algorithm_type="dpmsolver")

x_end = solver.sample(
    x_T,
    steps=n_steps,
    order=3,
    method="singlestep_fixed",   # pure DPM-Solver-3
    skip_type="logSNR",          # uniform in lambda = constant h
    t_end=1e-3,
    denoise_to_zero=False,
)

Three settings that will silently ruin your order measurement

method="singlestep_fixed". The default singlestep and multistep modes deliberately mix orders 1, 2 and 3 to spend the NFE budget exactly (appendix D.3). A convergence slope measured on those is meaningless. Only singlestep_fixed gives you clean DPM-Solver-k.

skip_type="logSNR". This is uniform in λ, i.e. constant step size — what "h" means for this method.

denoise_to_zero=False. It adds one NFE and moves the endpoint. Good for FID, wrong for measuring discretization error.

Also: actual NFE for singlestep_fixed is (steps // order) * order, which may be less than steps. The paper marks these cases with a dagger in Table 6. Record the real number.

Gate G1 — the identity that must hold

End of week one. Everything downstream depends on this.

Section 4.1 proves DDIM and DPM-Solver-1 are algebraically the same update. Since σ/α = e^(−λ), the DDIM coefficient α_i(e^(−λ_{i−1}) − e^(−λ_i)) equals σ_i(e^h − 1) exactly. Two independent implementations must therefore agree to machine precision.

tests/test_gate_g1.py

import numpy as np
from src.testbeds import GaussianTier1

        x = xT
        for tp, tc in zip(grid[:-1], grid[1:]):
            x = dpm_solver_1(tb.eps, x, tp, tc)
        errs.append(np.linalg.norm(x - ref))
        hs.append((lmbda(1e-3) - lmbda(1.0)) / n)
    slope = np.polyfit(np.log(hs), np.log(errs), 1)[0]

Measure order properly

Two days. Owner: measurement workstream.

The naive version — fit a line through all your points — will give wrong answers, because a real convergence curve has three regions. At large h you are pre-asymptotic and the theory does not apply. In the middle you get the true slope. At tiny h round-off takes over and the curve flattens or turns up. Fit only the middle.

src/metrics.py

import numpy as np

def fit_order(hs, errs, min_pts=4):
    """
    Sliding-window log-log fit. Returns the window with the best linear fit,
    which automatically excludes the pre-asymptotic and round-off regions.
    """
    hs, errs = np.asarray(hs, float), np.asarray(errs, float)
    ok = np.isfinite(errs) & (errs > 0)
    hs, errs = hs[ok], errs[ok]
    if len(hs) < min_pts:
        return dict(slope=np.nan, r2=np.nan, window=None)

    lx, ly = np.log(hs), np.log(errs)
    best = None
    n = len(lx)
    for i in range(n - min_pts + 1):
        for j in range(i + min_pts, n + 1):
            x, y = lx[i:j], ly[i:j]
            m, c = np.polyfit(x, y, 1)
            resid = y - (m*x + c)
            r2 = 1.0 - resid.var() / y.var() if y.var() > 0 else 0.0
            # prefer wide windows, but only if they stay straight
            score = r2 + 0.01*(j - i)
            if best is None or score > best["score"]:
                best = dict(score=score, slope=m, r2=r2,
                            window=(float(hs[i]), float(hs[j-1])), n=j-i)
    best.pop("score")
    return best

def l2(x, ref):
    return float(np.linalg.norm(np.asarray(x) - np.asarray(ref)))

Report the fit window and R² alongside every slope. A slope of 2.9 over four decades of h is a result; a slope of 2.9 over one decade with R² of 0.82 is noise. Your report table should have columns: solver, theoretical order, measured slope, fit window, R².

Stability envelope

One day. This is your most original result.

Section 4.2 claims explicit methods on semi-linear ODEs become unstable at large steps, cites the literature, and does not measure it. Measure it. For each solver and each κ, bisect on the number of steps to find the coarsest grid that still converges.

src/stability.py

import numpy as np
from .solvers import integrate
from .grids import grid_t, grid_lambda

def diverged(x, x_T, factor=10.0):
    return (not np.all(np.isfinite(x))) or \
           np.linalg.norm(x) > factor * np.linalg.norm(x_T)

def max_stable_h(tb, arm, stepper, T=1.0, t_end=1e-3,
                 n_lo=2, n_hi=4096):
    """
    Smallest step count that remains stable, by bisection.
    Returns the corresponding h, or nan if unstable even at n_hi.
    """
    rhs  = tb.rhs_t if arm == "A" else tb.rhs_lambda
    gfun = grid_t   if arm == "A" else grid_lambda
    xT   = tb.x_T(1)

    def stable(n):
        x, _ = integrate(rhs, xT, gfun(T, t_end, n), stepper)
        return not diverged(x, xT)

    if not stable(n_hi):
        return np.nan
    lo, hi = n_lo, n_hi                # lo unstable (assumed), hi stable
    if stable(lo):
        hi = lo
    else:
        while hi - lo > 1:
            mid = (lo + hi) // 2
            if stable(mid): hi = mid
            else:           lo = mid
    g = gfun(T, t_end, hi)
    return float(abs(g[1] - g[0]))

Sweep κ over {1, 10, 10², 10³, 10⁴} and all steppers in both arms. Plot h_max against κ. The expected story: arm A degrades sharply as κ grows because σ(t) → 0 near the end and the g²/(2σ) factor blows up, while arms B and C hold roughly flat. That plot alone justifies the project.

from scipy.special import logsumexp

class MixtureTier2:
    """Data = weighted point cloud. Exact score, real curvature."""

    def __init__(self, mu, w=None, seed=0):
        self.mu = np.asarray(mu, np.float64)          # (K, d)
        K = len(self.mu)
        self.logw = np.log(np.full(K, 1.0/K) if w is None else np.asarray(w))
        self.d = self.mu.shape[1]
        self.rng = np.random.default_rng(seed)

    def eps(self, x, t):
        a, sg = alpha(t), sigma(t)
        x = np.atleast_2d(x)                           # (N, d)
        diff = x[:, None, :] - a*self.mu[None, :, :]   # (N, K, d)
        logp = self.logw[None, :] - (diff**2).sum(-1) / (2*sg**2)
        r    = np.exp(logp - logsumexp(logp, axis=1, keepdims=True))
        x0   = np.einsum("nk,kd->nd", r, self.mu)      # posterior mean
        return (x - a*x0) / sg

    def rhs_t(self, x, t):
        return f(t)*x + g2(t)/(2.0*sigma(t)) * self.eps(x, t)

    def rhs_lambda(self, x, l):
        from .schedule import t_of_lmbda
        t = t_of_lmbda(l)
        return sigma_hat(l)**2 * x - sigma_hat(l) * self.eps(x, t)

    def x_T(self, n=1):
        return self.rng.standard_normal((n, self.d))

def swiss_roll(n=2000, noise=0.05, seed=0):
    rng = np.random.default_rng(seed)
    p = 1.5*np.pi*(1 + 2*rng.random(n))
    xy = np.stack([p*np.cos(p), p*np.sin(p)], axis=1) / 15.0
    return xy + noise*rng.standard_normal(xy.shape)

Tolerance floor

SciPy refuses rtol below about 2.2e-14 (100 × machine epsilon). Your deck says 1e-14 — use 1e-13 with atol=1e-14. Then check your reference is actually converged by recomputing at 1e-11 and confirming the two agree well below your smallest measured error.

Four things that will cost you a day each

The lambda. UNet2DModel returns a dataclass, not a tensor. model_wrapper expects a tensor. Without .sample you get an opaque error at 2 a.m.

Cache the reference. Recomputing 200-NFE trajectories is the single biggest time sink in this project. Save it to disk once and load it forever.

Same network, same x_T. The reference must use the identical checkpoint and identical starting noise. You are measuring discretization error, not model error.

float32 floors the measurement around 1e-3 relative. Convergence curves will flatten there. Do not fit slopes through the flat part — instead, report where it flattens. That is a finding: the point past which solver order stops mattering because network precision dominates.

Total error on Tier 3 has three components, not one: discretization error, truncation from stopping at t_end instead of 0, and network approximation error. Your deck discusses only the first. Decomposing all three is cheap and genuinely explanatory — and it explains the odd fact in the next step.
